# Operation Manual (運用マニュアル)

結婚式写真投稿アプリの「事前準備」「当日運用」「事後対応」の手順書です。

## 1. 事前準備 (Preparation)

### 1-1. 認証トークン & QRコードの発行
ゲストがログインするためのURLとQRコードを生成します。
セキュリティ担保のため、テーブルごとに異なるUUID（認証トークン）を発行します。

1.  **トークン生成スクリプトの実行**
    ```bash
    # プロジェクトのルートで実行（スクリプトは scripts/generate_tokens.ts を想定）
    npm run generate-tokens
    ```
    **出力:** `tokens.csv` (トークン一覧) と `qr_codes/` (QR画像フォルダ) が生成されます。

2.  **DynamoDBへの登録**
    生成された `tokens.csv` のデータを、DynamoDBの `Wedding_GuestAuth` テーブルにインポートします。
    ```bash
    npm run seed-db
    ```

### 1-2. 特権管理者（裏・管理人）の準備
不適切な写真を削除するための「管理者用QRコード」を1つ用意します。

* **テーブル名:** ADMIN
* **権限:** 全テーブルの写真を削除（非表示）できる権限を付与（※実装側で `role: 'ADMIN'` は全削除許可とするロジックを入れる）。
* **配布:** 信頼できる友人（または新郎新婦の予備スマホ）にこのQRコードを読み込ませておく。

### 1-3. 印刷物への配置
* **各卓:** 対応するテーブルIDのQRコードを席次表や卓上ポップに印刷。
* **注意書き:** 以下の文言を添えるとスムーズです。
    > 「撮影した写真は5分後に会場スクリーンへ投影されます」
    > 「間違ってアップした写真は、自分のスマホから削除できます」

## 2. 当日の運用 (Live Operation)

### 2-1. ゲストの利用フロー
1.  卓上のQRコードをカメラで読み取る。
2.  アプリが開き、自動的にログイン完了（JWT発行）。
3.  写真を撮影・選択してアップロード。
4.  **削除:** 自分のテーブルのメンバーが上げた写真は、一覧画面に「ゴミ箱🗑️」が表示されるので、誤操作時はそこから削除可能。

### 2-2. スライドショーの運用
* **機材:** 会場のプロジェクターに接続されたPC（またはiPad）。
* **URL:** `https://your-app.com/slideshow`
* **操作:** ブラウザを全画面表示 (F11) にし、放置するだけでOK。
    * 5分間のタイムラグを経て、新しい写真が自動で流れます。

### 2-3. トラブルシューティング

| 事象 | 原因の可能性 | 対応策 |
| :--- | :--- | :--- |
| **QRコードが読み取れない** | 会場が暗い / 印刷が小さい | スマホのライトをつけてもらう / URLを直接入力してもらう（予備策） |
| **アップロードが遅い** | 会場の電波状況が悪い | Wi-Fiへの接続を案内する / 「後で送ってね」と伝える |
| **変な写真が表示された** | ゲストの悪ふざけ | **管理者（友人）**の手元のスマホから即座に削除（非表示）ボタンを押す。 |
| **「エラーが発生しました」** | サーバー側の一時的な高負荷 | 数秒待ってからリトライしてもらうよう案内。 |

## 3. 事後対応 (Post-Event)

式終了後、翌日以降に行う作業です。

### 3-1. 写真データの一括回収
S3に保存された全データをローカルPCにダウンロードします。

```bash
# 事前にAWS CLIの設定が必要です
# photos/ ディレクトリにダウンロードされます
aws s3 sync s3://YOUR_BUCKET_NAME/photos ./wedding_photos_backup
```

構造: wedding_photos_backup/TABLE_A/xxx.jpg のようにテーブルごとにフォルダ分けされて保存されます。

### 3-2. クラウド破産防止（リソース削除）
思い出の回収が完了し、アプリの公開期間（例: 10日）が過ぎたら、課金を止めるためにリソースを削除します。

#### S3バケットを空にする (空にしないとStack削除に失敗します)

```bash
aws s3 rm s3://YOUR_BUCKET_NAME --recursive
```

#### CloudFormationスタックの削除

```bash
cdk destroy
```

注意: DynamoDBのデータも消えるため、必要な場合は事前にエクスポートしてください。

### 4. 環境変数 (Environment Variables)
開発およびデプロイに必要な環境変数一覧です。

| 変数名 | 説明 | 例 |
| :--- | :--- | :--- |
| **AWS_REGION** | リージョン | `ap-northeast-1` |
| **S3_BUCKET_NAME** | 画像保存バケット名 | `wedding-photos-202X` |
| **API_ENDPOINT** | Lambda APIのエンドポイント | `https://xxx.execute-api...` |
| **EVENT_ID** | イベント識別子 | `WEDDING_2024_TARO_HANAKO` |
